# Internationalization (i18n)

All user-visible text that may need localization should use the Taon translation system.

## Frontend

Use the Taon translation system in Angular components, services, directives, and other frontend code.

### Component setup

Create the translation helper once at file level:

```ts
import { Taon } from 'taon/src';
import { Translation } from '@taon-dev/i18n/src';

const t = Translation.for(
  Taon.__FILE_RELATIVE_PATH,
  Taon.LANG_IMPORT_MAP,
);

@Component({
  selector: 'my-component',
  // ...
})
export class MyComponent {
  //#region injections

  t = t.for(this);

  //#endregion

  signalLabel = this.t.signal.gettext('Label signal');

  signalWithParams = this.t.signal.gettext('Params: [[ test ]]', {
    test: 'test param',
  });

  normalLabel = this.t.gettext('Normal label');

  normalLabelWithContext = this.t.gettext(
    'Normal label',
    {},
    'context of translation',
  );

  refresh = new BehaviorSubject({});

  valueInsideComponent = 'dynamic!';

  observableLabel$ = this.refresh.asObservable().pipe(
    switchMap(() =>
      this.t.$.gettext('I am [[ dynamicParam ]]', {
        dynamicParam: this.valueInsideComponent,
      }),
    ),
  );
}
```

### Choosing the translation API

Choose the simplest API appropriate for the value.

#### 1. Signal translation

Prefer Signal-based translations for values that should reactively update when the active language changes:

```ts
signalLabel = this.t.signal.gettext('Label signal');
```

Parameters are supported:

```ts
signalWithParams = this.t.signal.gettext('Params: [[ test ]]', {
  test: 'test param',
});
```

Use `[[ paramName ]]` placeholders for dynamic translation parameters.

#### 2. Normal synchronous translation

Use `gettext()` when a reactive value is not needed:

```ts
normalLabel = this.t.gettext('Normal label');
```

Use the optional context argument when identical source text may require different translations depending on its meaning:

```ts
normalLabelWithContext = this.t.gettext(
  'Normal label',
  {},
  'context of translation',
);
```

#### 3. Observable translation

Use the Observable API only when the translated value naturally belongs to an existing RxJS flow:

```ts
observableLabel$ = this.refresh.asObservable().pipe(
  switchMap(() =>
    this.t.$.gettext('I am [[ dynamicParam ]]', {
      dynamicParam: this.valueInsideComponent,
    }),
  ),
);
```

Do NOT introduce an Observable solely for translation when a normal or Signal-based translation is sufficient.

### Template usage

Translations may be consumed directly in Angular templates:

```html
<span>{{ signalLabel() }}</span>

<span>{{ signalWithParams() }}</span>

<span>{{ normalLabel }}</span>

<span>{{ normalLabelWithContext }}</span>

<span>{{ observableLabel$ | async }}</span>

<span>{{ t.gettext('This also works!') }}</span>

<!-- only when TranslateDirective included in imports -->
<span translate>This will also be translated!</span>
```

### Frontend rules

- Translate user-visible text when appropriate.
- Do NOT hardcode text in TypeScript when that text should be localized.
- Prefer Signals for reactive translations.
- Use normal `gettext()` for simple synchronous translations.
- Use `t.$.gettext()` only when working naturally inside an RxJS flow.
- Do NOT create RxJS streams just to translate a value.
- Use translation context when the same source text can have different meanings.
- Use `[[ param ]]` placeholders instead of manually concatenating dynamic values into translation strings.
- if you use `TranslateDirective` => you still needs to assign "t" variable to Component body `t = t.for(this)`;

## Backend

Backend translation works differently from frontend translation.

Taon provides a request-specific translation instance through the third argument of the controller handler.

The language is associated with the current request and may be detected from request information such as cookies.

### Important: do NOT create the frontend translation helper

Do NOT do this in a Taon backend controller:

```ts
// 🚫 DO NOT USE THIS FOR CONTROLLER REQUEST TRANSLATION

const t = Translation.for(
  Taon.__FILE_RELATIVE_PATH,
  Taon.LANG_IMPORT_MAP,
);
```

This pattern is intended for Angular/frontend classes such as components, services, and directives.

For controller request translation, always use the `t` supplied to the request handler:

```ts
return async (req, res, { t }) => {
  // use t here
};
```

### Backend translations are synchronous

Inside the request handler, use the synchronous translation API.

Do NOT use:

- `t.signal`
- `t.$`
- translation Signals
- translation Observables

Use:

```ts
t.gettext(...)
```

or, when translating arbitrary/dynamic text:

```ts
t.translate(...)
```

### Translate using the request language

```ts
@TaonController({
  className: 'ExampleController',
})
export class ExampleController extends TaonBaseController {
  @GET()
  helloWorld(
    @Query('yourName') yourName: string,
  ): Taon.Response<string> {
    //#region @websqlFunc
    return async (req, res, { t }) => {
      return `${t.gettext('Hello')} : ${yourName}`;
    };
    //#endregion
  }
}
```

Here, `t` uses the language detected for the current request.

### Force a specific language

When a response must use a specific language regardless of the request language, explicitly change it:

```ts
@GET()
helloWorldInFrench(
  @Query('yourName') yourName: string,
): Taon.Response<string> {
  //#region @websqlFunc
  return async (req, res, { t }) => {
    t.changeFileLang('fr-FR');

    return `${t.gettext('Hello')} : ${yourName}`;
  };
  //#endregion
}
```

Do not force a language unless the feature specifically requires it.

### Translate arbitrary text

For arbitrary text that is not a predefined `gettext()` translation entry, use `translate()`:

```ts
@POST()
translateSomethingUnknown(
  @Body('bigText') bigText: string,
): Taon.Response<string> {
  //#region @websqlFunc
  return async (req, res, { t }) => {
    t.changeFileLang('es-ES');

    return t.translate(bigText);
  };
  //#endregion
}
```

### Backend rules

- Always obtain `t` from the third controller-handler argument: `{ t }`.
- Treat `t` as request-specific.
- Use `t.gettext()` for known application strings.
- Use `t.translate()` for arbitrary/dynamic text.
- Use `t.changeFileLang(...)` only when the endpoint explicitly needs to override the detected request language.
- Do NOT create a frontend-style `Translation.for(...)` instance for controller request translation.
- Do NOT use Signals or Observables for backend translation.
- Do NOT introduce frontend translation patterns into backend controller handlers.
